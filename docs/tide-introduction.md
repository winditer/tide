# Tide — AI 编程助手统一调度平台

## 一、Tide 是什么

### 1.1 定位

**Tide** 是一个面向开发团队的 AI 编程助手统一调度平台。它将 Codex、Claude Code、Qoder 等多种 Agent CLI 统一封装于单进程 FastAPI 后端之上，通过 Next.js Web 工作台与飞书（Lark）双通道，为团队提供**从需求拆解到代码交付的端到端自动化能力**。

简单来说，Tide 做的事情是：

> **把散落在各处的 AI 编程工具变成一个可管控的企业级平台，让团队像调度流水线一样调度 AI Agent 完成开发工作。**

### 1.2 核心价值链

```
长文本 PRD/需求
    ↓ AI 自动拆解
工作项清单（可编辑校对）
    ↓ 智能路由
分发到正确的仓库/模块
    ↓ 工作流 DAG 编排
多 Agent 并行执行（Git worktree 隔离）
    ↓ 产物汇总 + 审批
代码合并 → 冲突自动解决 → 知识图谱更新 → 成本统计
```

### 1.3 一句话总结

Tide = **多 Agent 统一调度** + **DAG 工作流编排** + **跨仓库协作** + **企业级治理能力**。

## 二、特点和核心功能

### 2.1 架构层面的特点

| 特点 | 说明 |
|------|------|
| **单进程自托管** | 一个进程承载 HTTP、WebSocket、Agent 执行、定时调度、Lark 监听，无 Redis/消息队列依赖 |
| **SQLite 唯一数据源** | 所有状态写库持久化，WAL 并发模式，crash-safe |
| **不重造 Agent 运行时** | 复用现有 CLI（Codex/Claude/Qoder），后端只做控制面 |
| **双入口并存** | Web 工作台为第一入口，Lark Bot 辅助；缺凭据自动降级为 Web-only |
| **Git 原生隔离** | 每个任务独立 worktree + 分支，并行安全，互不干扰 |
| **Monorepo 前端** | Next.js 16 + React 19 + TypeScript，packages 分层（core/ui/views） |

### 2.2 核心功能一览

| 功能域 | 核心能力 |
|--------|---------|
| **任务管理** | 创建/执行/停止/重试/审批，SSE 流式输出，会话续写 |
| **Plan 并行编排** | DAG 依赖关系、阶段化执行、Git 隔离、合并总览 |
| **工作流引擎** | 可视化 DAG 编辑器，Agent/审批/条件/并行/延时/Git Merge 六种节点 |
| **工作项与 AI 分解** | 长文本一键拆工作项，编辑校对后批量创建 |
| **看板系统** | 项目/会话/Agent/工作流/工作项五维看板，拖拽改状态 |
| **知识图谱** | 10 类自动生成（模块/API/Schema/概念/架构/技术栈/编码风格/数据流/测试/事件） |
| **企业能力中心 (ECC)** | Skills 技能库 + Rules 规则 + Hooks 事件 + Security 安全 + Cost 成本 + Expert Teams |
| **定时调度** | Cron/Interval/Date 三种触发器，执行历史，启停开关 |
| **Lark 双通道** | Bot 消息触发任务、指令快捷操作、审批同步、卡片状态刷新 |
| **远程 Agent (A2A)** | 标准 Agent-to-Agent 协议桥接，支持分布式 Agent 执行 |

### 3.2 Tide 的差异化优势

**相比 AI IDE 工具（Cursor、Windsurf、Copilot）**：
- Tide 不替代 IDE，而是站在 IDE 之上做**调度和编排**。开发者仍可在自己喜欢的编辑器中工作，Tide 负责分配任务给不同的 Agent 并管理整个执行生命周期。
- 支持**多种 Agent 混合编排**，而非绑定单一模型。

**相比自主 Agent（Devin）**：
- Tide 不做"黑盒全自动"，强调**人机协同**——任务可审批、产物可校对、流程可编排。
- 完全自托管，代码和数据不出企业网络。
- 支持团队协作而非单人使用。

**相比项目管理工具（Linear、Jira）**：
- Tide 的看板和工作项不是"记录工具"，而是**驱动 Agent 执行的工作单元**——创建工作项即可触发 AI 自动执行。
- 工作流是真正的 DAG 编排引擎，而非简单的状态流转自动化。

### 3.3 适用场景定位

```
传统项目管理 ← Linear/Jira
AI 辅助编码  ← Cursor/Copilot/Windsurf
自主 AI 编码 ← Devin
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

```

Tide 补的是**从"单人 AI 编码"到"团队 AI 工程化"之间的空白**。

## 四、解决的实际问题

### 4.1 微服务/多仓库项目的痛点

在大型微服务项目中，一个需求往往需要跨越多个仓库修改。传统做法：

```
产品 PRD → 人工拆分为前端/后端/基础设施子任务
         → 各团队各自领取
         → 手动协调接口契约
         → 反复沟通解决冲突
         → 集成测试发现问题回滚
```

Tide 的解法：

```
产品 PRD → AI 自动拆解工作项
         → 智能路由到正确仓库（基于知识图谱）
         → 工作流编排多 Agent 并行执行
         → Git worktree 隔离，互不干扰
         → 自动测试 + 审批 + 合并（冲突自动解决）
```

### 4.2 具体解决的问题

| 问题 | Tide 的解法 |
|------|------------|
| **Agent 工具碎片化** | 统一调度 Codex/Claude/Qoder，一个平台管理所有 Agent |
| **跨仓库需求协调** | 项目组聚合 + 智能路由 + 跨仓库 Plan |
| **AI 产物质量不可控** | Rules 强制约束 + Security 安全扫描 + Hooks 事件驱动 |
| **执行过程不透明** | SSE 实时输出 + Git 审计四维视图 + Token 成本追踪 |
| **代码冲突频发** | Worktree 原生隔离 + Git Merge 智能冲突解决 |
| **知识积累断层** | 10 类知识图谱自动生成，项目上下文持续更新 |
| **重复性工程工作** | 定时调度 + 工作流自动触发 + 批量工作项 |
| **审批流程缺失** | Web + Lark 双端审批，审批策略可配置 |

### 4.3 典型场景示例

**场景：微服务项目新增一个 API 功能**

1. 产品在 Lark 群发送需求文本
2. Tide 的 AI 分解自动拆为：后端 API + 数据库迁移 + 前端页面 + 文档更新
3. 智能路由将每个工作项分发到正确仓库
4. 工作流按 DAG 编排：先后端→再前端→最后文档
5. 每个 Agent 在独立 worktree 中工作，互不阻塞
6. 执行完成后触发测试 → 审批 → 自动合并
7. 产物汇总展示在浮动聊天面板，知识图谱自动更新

## 五、特色功能详解

### 5.1 浮动聊天

**位置**：屏幕右下角可拖拽悬浮面板

浮动聊天不是简单的 ChatGPT 对话框，而是**任务执行的实时窗口**：

- **实时输出**：Agent 执行过程通过 SSE 流式推送到聊天窗口
- **产物汇总**：自动收集 Agent 生成的文件（代码/文档/配置），折叠面板展示
- **在线预览**：点击产物即可在线查看（JSON/代码/Markdown/图片）
- **续聊能力**：对话上下文保持，可基于历史继续追问或修改
- **多会话管理**：不同项目/任务的对话隔离，互不干扰

### 5.2 AI 智能分解

将长文本 PRD 或需求描述一键拆解为结构化工作项：

```
输入（支持三种方式）：
├─ 长文本粘贴（PRD/需求文档）
├─ 链接输入（文档 URL）
└─ 文件上传（.md/.txt/.docx/.pdf，单文件 10MB）

AI 分析：
└─ 调用 LLM 自动识别任务边界、依赖关系、优先级

输出 + 校对：
├─ 编辑标题/描述/优先级
├─ 手动增删条目
├─ 调整顺序和依赖
└─ 确认后批量创建工作项
```

**与传统需求管理的区别**：不只是记录，创建即触发执行流——工作项进入工作流后自动分配 Agent 执行。

### 5.3 工作流即项目流程

Tide 的工作流不是"画个图看看"的 BPMN 装饰品，而是**真正驱动代码生产的执行引擎**：

**六种节点类型**：

| 节点 | 作用 | 典型使用 |
|------|------|---------|
| **Agent** | 执行 AI 编程任务 | 代码编写、代码审查、文档生成 |
| **Approval** | 等待人工审批 | 代码合并前审批、关键变更确认 |
| **Condition** | 条件分支判断 | 测试通过→合并，失败→通知修复 |
| **Parallel** | Fork 并行 + Join 汇聚 | 前后端同时开发，全部完成后集成 |
| **Delay** | 定时延迟 | 等待 CI 完成、限流控制 |
| **Git Merge** | 代码分支合并 | 自动将 Agent 产物合入主分支 |

**实际工作流示例**：
```
需求工作项进入 →
  Agent①（生成技术方案） →
  Approval（方案审批） →
  Parallel [
    Agent②（后端实现，worktree 隔离）
    Agent③（前端实现，worktree 隔离）
  ] → Join →
  Agent④（集成测试） →
  Condition（测试通过？）→
    Yes → Git Merge（合入 main）→ 完成
    No  → Agent⑤（修复）→ 回到测试
```

每个 Agent 节点支持独立配置：Agent 类型、模型、专家团角色、Skills/Rules 注入、worktree 隔离策略。

### 5.4 任务续聊与会话恢复

**续聊**不是"重新开一个对话"，而是真正基于之前的上下文继续：

- **Session Resume**：任务完成后可在原会话上追加新指令，Agent 保持完整上下文
- **跨 Agent 续聊**：支持切换 Agent 继续处理同一会话（如 Codex 写完后切 Claude 审查）
- **浮动聊天续聊**：在浮动面板内直接回复，无需跳转页面
- **Plan 任务续聊**：Plan 子任务完成后可针对单个子任务续聊修改

### 5.5 Lark 指令系统

在飞书群内通过 Bot 消息直接操作 Tide：

| 指令 | 功能 |
|------|------|
| 直接发送文本 | 使用默认 Agent 执行任务 |
| `/agent=claude 任务描述` | 指定 Agent 执行 |
| `/plan 阶段描述...` | 创建并行 Plan |
| `/approve <id>` | 审批通过 |
| `/reject <id>` | 审批驳回 |
| `/stop` | 停止当前任务 |
| `/cancel <id>` | 取消指定任务 |

**双向同步**：
- Lark → Web：在飞书触发的任务，Web 端实时同步状态
- Web → Lark：在 Web 端的操作，Lark 卡片自动刷新

## 六、如何开展项目协作

### 6.1 快速开始

```bash
# 方式一：Docker Compose 一键部署
cp .env.example .env
# 编辑 .env 配置 Agent 密钥和可选的 Lark 集成
docker compose up -d --build

# 方式二：本地开发
pip install -r backend/requirements.txt
uvicorn backend.main:app --reload --host 0.0.0.0 --port 8000
cd apps/web && yarn install && yarn dev
```

### 6.2 团队协作流程

**Step 1：项目接入**

- 在 Web 工作台添加 Git 仓库（支持 SSH/HTTPS 认证）
- 配置默认 Agent 和 模型
- 如有多个关联仓库，创建项目组聚合管理

**Step 2：配置工作流**

- 使用 React Flow 可视化编辑器设计项目专属工作流
- 配置 Agent 节点的专家团角色、Skills、Rules
- 设置审批策略（自动/手动/条件触发）

**Step 3：日常协作**

```
产品/开发 → 提交需求（Web 或 Lark）
           ↓
Tide → AI 分解 + 智能路由
           ↓
Agent → 自动执行（Git 隔离）
           ↓
团队 → 审批 + 续聊修改
           ↓
Tide → 自动合并 + 产物交付
```

**Step 4：持续优化**

- 查看 Dashboard 了解任务执行统计和成本
- 通过 Git 审计追踪代码变更
- 利用知识图谱保持项目文档自动更新
- 根据 Hook 事件驱动安全扫描和质量检查

### 6.3 角色分工

| 角色 | 在 Tide 中的活动 |
|------|-----------------|
| **产品经理** | 提交 PRD → AI 分解 → 审批工作项 |
| **技术负责人** | 设计工作流 → 配置规则/技能 → 审批代码变更 |
| **开发者** | 续聊调整 → 查看产物 → 处理冲突 |
| **DevOps** | 配置定时调度 → 管理远程 Agent → 监控成本 |

### 6.4 企业治理

通过 ECC（企业能力中心）实现全方位治理：

- **Skills 技能库**：沉淀团队 Prompt 经验，所有 Agent 自动加载
- **Rules 规则引擎**：三层分级约束（全局 → 语言 → 项目），强制注入 Prompt 顶部
- **Hooks 事件驱动**：任务状态变更时自动触发动作（安全扫描/通知/脚本）
- **Security 安全审查**：正则扫描 Agent 输出，检测密钥泄露/质量/合规问题
- **Cost Tracking**：按 Agent/模型/项目维度追踪 Token 用量与费用
- **Expert Teams**：预设 Agent + Skills + 角色提示词组合，一键复用
